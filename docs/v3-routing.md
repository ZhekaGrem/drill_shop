# v3 поруч із бойовим v2

Ця гілка додає лише зовнішній rewrite `/v3/:path*` і передає обробку сесій під цим префіксом middleware самого v3. Кореневі сторінки залишаються v2.

1. Розгорнути гілку `v3` окремим production-проєктом Vercel із тими самими змінними середовища магазину та `NEXT_PUBLIC_STOREFRONT_BASE_PATH=/v3`.
2. Переконатися, що його `/v3` доступний без входу у Vercel. Захищені preview-адреси не підходять для публічного rewrite.
3. Застосувати коміт цієї гілки до `v2`.
4. У Production проєкту, якому належить `ye-dril.com`, додати `V3_STOREFRONT_ORIGIN=https://<публічний-домен-v3>` без `/v3` наприкінці. Redeploy гілки `v2`.
5. Перевірити основну `/` та `/v3`, каталог, товар, кошик, checkout, auth та Moto. Звичайний `<a>` використовувати для переходів між зонами.

Без `V3_STOREFRONT_ORIGIN` rewrite вимкнений. Для відкату прибрати змінну та redeploy v2. Основний домен не потрібно переносити на новий проєкт.

Локальна перевірка: окремий production v3 на 3004, v2 dev на 3005 із `V3_STOREFRONT_ORIGIN=http://127.0.0.1:3004`. `check-v3-mount.mjs` з гілки v3 пройшов через проксі: 12 сторінок, 98 асетів, admin redirect та API. Реальних замовлень, оплат чи повідомлень не створює.
