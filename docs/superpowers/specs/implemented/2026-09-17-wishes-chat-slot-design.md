# Побажання покупців: слот чату в навбарі, шторка, доставка в Telegram

**Дата:** 2026-09-17
**Гілка:** `v2`
**Статус:** спека затверджена по секціях, план не написаний

---

## Задача

Зібрати побажання покупців щодо нових або кращих товарів, не додаючи на сайт
жодного постійного елемента. Кнопка меню в правій групі хедера періодично
«тане в блюрі», і замість неї на той самий час зʼявляється кнопка чату. Тап
по ній відкриває нижню шторку з одним запитанням: «Що нам ще розробити?».
Текст побажання разом із контактом (за бажанням) летить у той самий
адмін-чат Telegram, куди вже приходять замовлення й запити «чекаю».

## Рішення, зафіксовані з власником

| Питання                | Рішення                                                                                                                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Такт підміни           | 5 с показується меню, 5 с замість нього кнопка чату. По колу, без зупинки, поки відкрита вкладка.                                                                           |
| Поверхня форми         | Нижня шторка `shared/components/Sheet` (мова Дії на телефоні). Не модалка, не окрема сторінка.                                                                              |
| Контакт                | Одне необовʼязкове поле «Телефон або Telegram», без суворої перевірки формату.                                                                                              |
| Доставка               | Той самий адмін-чат (`TELEGRAM_CHAT_ID`), тег `#побажання`. Нових змінних середовища нема.                                                                                  |
| Постійний вхід у /menu | Ні. Єдиний вхід — кнопка чату в навбарі.                                                                                                                                    |
| Email залогіненого     | Ні. У повідомлення йде лише те, що людина сама написала.                                                                                                                    |
| Платформа              | Лише веб-хедер. У Telegram Mini App хедера нема, і людина вже в Telegram.                                                                                                   |
| Десктоп                | Слот успадковує видимість кнопки меню: `.iconButton` прихована від 1024px (рішення власника 2026-09-02), тож фіча живе на ширинах до 1023px. На десктопі кнопки чату немає. |

Останній рядок — наслідок наявної розкладки, а не окреме побажання власника.
Якщо десктопу потрібен вхід, це окреме рішення: на десктопі нема кнопки меню,
яку можна підмінити, тож кнопка чату там мусила б стояти сама по собі.

## Слот у хедері

### Розмітка

`Header.tsx` замість `<Link href="/menu">` рендерить `<MenuSlot />`
(новий файл `widgets/Header/MenuSlot.tsx`). Слот — обгортка 44×44 із двома
дітьми, що лежать одна на одній абсолютно:

- **меню** — той самий `Link` на `/menu` з `MenuIcon`, класи не змінюються;
- **чат** — `<button type="button">` з новою `IconChat`, `aria-label`
  «Запропонувати ідею», по кліку відкриває шторку.

Обгортка `.slot` повторює медіа-правило `.iconButton`
(`@media (min-width: 1024px) { display: none }`), інакше на десктопі лишиться
порожній 44px проміжок між «Каталогом» і кошиком.

### Такт: `widgets/Header/useSlotAlternation.ts`

- Фаза `'menu' | 'chat'`, стартова `'menu'`. Стартове значення однакове на
  сервері й клієнті, таймер запускається лише в `useEffect` — гідрація не
  розходиться.
- `SLOT_PERIOD_MS = 5000`. Один `setInterval`; кожен тік перемикає фазу.
- **Утримання.** Поки на слоті ховер (`pointerenter`/`pointerleave`) або
  фокус усередині (`focusin`/`focusout`), тік пропускається: кнопка не зникає
  з-під пальця чи курсора. Наступна перевірка — через звичайні 5 с.
- **Пауза.** Хук приймає `paused: boolean` (шторка відкрита). На паузі
  інтервалу нема; при знятті паузи фаза скидається на `'menu'` і відлік
  починається заново — після закриття шторки людина бачить звичний хедер.
- **Прихована вкладка.** На `visibilitychange` → `visible` фаза скидається на
  `'menu'`, інтервал перезапускається. Браузери тротлять таймери у фоні, і
  без скидання вкладка могла б повернутись «залиплою» на чаті.
- Хук повертає `{ phase, holdHandlers }`; `holdHandlers` вішаються на
  обгортку слота.

### Перехід «тане в блюрі»

Стилі в `header.module.scss`:

```scss
.slot {
  position: relative;
  width: 44px;
  height: 44px;
  @media (min-width: 1024px) {
    display: none;
  }
}
.slotItem {
  position: absolute;
  inset: 0;
  transition:
    opacity var(--dur-modal) var(--ease-in-out),
    filter var(--dur-modal) var(--ease-in-out),
    transform var(--dur-modal) var(--ease-in-out);
  &[data-shown='false'] {
    opacity: 0;
    filter: blur(6px);
    transform: scale(0.9);
  }
}
@media (prefers-reduced-motion: reduce) {
  .slotItem {
    transition: opacity var(--dur-modal) var(--ease-in-out);
    &[data-shown='false'] {
      filter: none;
      transform: none;
    }
  }
}
```

Обидві кнопки анімуються одночасно: стара розмивається і зникає, нова
приходить зворотним шляхом. Тривалість `--dur-modal` (220 мс) — це «поява
шару», а не «морфінг на екрані», тому не `--dur-sheet`. Blur на елементі
44×44 дешевий; застереження DESIGN_SYSTEM.md про blur стосується скелетонів
на весь блок.

### Доступність

- Прихована кнопка отримує атрибут `inert` (React 19 підтримує його як
  булевий проп): вона випадає з табу, з дерева доступності й не ловить
  кліки протягом 220 мс переходу. Окремих `aria-hidden`/`tabIndex` не треба.
- Live-region свідомо нема: оголошувати зміну кожні 5 с — шум для скрінрідера.
- Обидві кнопки — ціль 44×44, як решта правої групи (WCAG 2.5.5).
- Клавіатура: поки фокус на слоті, підміни не буде (правило утримання), тож
  Enter завжди спрацьовує на тій кнопці, яку людина бачить.

### Іконка

`shared/components/Svg/IconChat.tsx` за зразком `MenuIcon`: `viewBox 0 0 24 24`,
`stroke="currentColor"`, `strokeWidth 1.75`, круглі кінці. Бульбашка
повідомлення без хвостика-«трикутника» під обріз, у тому ж оптичному розмірі,
що три лінії бургера. Експорт у `Svg/index.ts`.

## Шторка: `features/wishes/components/WishSheet.tsx`

### Контракт

```ts
interface WishSheetProps {
  opened: boolean;
  onClose: () => void;
}
```

Стан `opened` тримає `Header` поруч із `CartDrawer`; `MenuSlot` отримує
`onOpenWishes`. Шторка рендериться в `Header` після `CartDrawer`.

### Вміст, зверху вниз

1. Заголовок шторки (`title` у `Sheet`): **Що нам ще розробити?**
2. Тихий підпис `--text-secondary`: «Розкажи, чого бракує. Читаємо все.»
3. `TextareaField` — обовʼязкове поле, лейбл «Побажання», плейсхолдер
   «Я би хотів, щоб ви розробили штани», `autosize minRows={3} maxRows={6}`,
   `maxLength={1000}`.
4. `Input` — необовʼязкове, лейбл «Телефон або Telegram», плейсхолдер
   «+380… або @нік», `maxLength={100}`, `autoComplete="tel"`.
5. Honeypot: `<input name="website">` у класі візуального приховування,
   `tabIndex={-1}`, `autoComplete="off"`, `aria-hidden`. Людина його не бачить.
6. Кнопки: `Button variant="primary" type="submit" fullWidth` «Надіслати»;
   під нею `Button variant="ghost" fullWidth` «Закрити» → `onClose`.

Автофокусу на текстове поле немає: на телефоні він одразу підіймає
клавіатуру і смикає шторку. Поле отримує фокус тапом.

### Стани

`status: 'idle' | 'sending' | 'sent' | 'error'`.

- **idle** — форма. Сабміт із порожнім (після `trim`) або коротшим за 3
  символи текстом не відправляє: поле стає в `error` із підписом «Напиши
  хоч кілька слів». Це єдина клієнтська перевірка.
- **sending** — кнопка «Надіслати» в `loading`, поля `disabled`.
- **sent** — тіло шторки замінюється на «Дякуємо!» + «Ми прочитаємо і
  подумаємо.» і `Button variant="primary" fullWidth` «Готово» → `onClose`.
  Поля очищаються.
- **error** — форма лишається з введеним текстом, під кнопками рядок
  `role="alert"`: «Не надіслалось. Спробуй ще раз або напиши нам у
  Telegram», де «Telegram» — лінк на `siteConfig.socials.telegram`.

Закриття шторки в будь-якому стані повертає `idle` при наступному відкритті;
введений текст у стані `error` при закритті губиться — чернетки поза межами.

### Що шле клієнт

`features/wishes/api/wishes-api.ts`:

```ts
interface WishRequest {
  message: string;
  contact?: string;
  page: string; // window.location.pathname
  website?: string; // honeypot, у людини завжди ''
}
interface WishResponse {
  success: boolean;
  message?: string;
}
sendWish(data: WishRequest): Promise<WishResponse>;
```

`fetch('/api/telegram/wishes', { method: 'POST' })`, як у
`notify-availability/api/notify-api.ts`. Неуспішна відповідь або мережева
помилка → `throw`, шторка переходить у `error`.

## API-роут: `src/app/api/telegram/wishes/route.ts`

- `POST`, тіло JSON `WishRequest`. Без авторизації, як два наявні роути.
- **Honeypot:** якщо `website` непорожній — відповідь `200 { success: true }`,
  у Telegram нічого не йде. Бот не має дізнатись, що його впіймали.
- **Валідація (сервер, не довіряти клієнту):** `message` після `trim` від 3
  до 1000 символів, інакше `400` з `{ success: false, message: 'Напиши хоч кілька слів' }`;
  `contact` — рядок до 100 символів або відсутній, довший обрізається до 100;
  `page` — рядок до 200 символів, що починається з `/`; інакше рядок
  «Сторінка» у повідомленні пропускається.
- Конфігурація: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; їх відсутність →
  `500 { success: false, message: 'Помилка конфігурації' }` і `console.error`.
- Виклик `https://api.telegram.org/bot<token>/sendMessage` **без
  `parse_mode`**. Наявні роути шлють Markdown, і зірочка чи підкреслення в
  тексті користувача там ламає відправку. Тут текст плоский.
- Текст повідомлення:

```
#побажання
Побажання з сайту

<message>

Контакт: <contact або «не залишено»>
Сторінка: <siteConfig.url><page>
Час: <toLocaleString('uk-UA', { timeZone: 'Europe/Kyiv' })>
```

`timeZone` вказано явно: Vercel живе в UTC, наявні роути через це пишуть
час на три години раніше.

- Успіх → `200 { success: true }`. Помилка Telegram → `500 { success: false,
message: 'Помилка відправлення' }`.

## Крайові випадки

- **Клік у момент переходу.** Прихована кнопка `inert`, тож клік у перехідні
  220 мс потрапляє або в ту, що зʼявляється (вона вже не `inert`), або в
  порожнє місце. Кнопка, що зникає, не спрацьовує.
- **Свайп хедера.** Слот у правій групі, яка в жесті не бере участі
  (`headerRight` поза доріжкою) — як і зараз для кошика.
- **Шторка відкрита, людина гортає сайт.** Mantine Drawer блокує скрол і
  тримає фокус; такт на паузі.
- **Відповідь 400 з сервера** (клієнт пропустив, сервер ні) → стан `error`
  з тим самим рядком; окремого тексту для 400 нема.
- **Telegram недоступний** → 500 → `error`. Повторний тап «Надіслати» шле
  ще раз; дублікатів не буде, бо перша спроба не дійшла.
- **Два хедери.** `Header` рендериться один раз у `LayoutWrapper`, тож і
  таймер один.

## Ручна перевірка

Автотестів у проєкті немає (без тестових залежностей і скрипта), тож
критерії готовності — ручні:

1. `npx tsc --noEmit` чистий. `npm run lint` у проєкті зараз падає на
   конфігурації (плагін `react-hooks` не знаходиться) — не критерій.
2. Телефон або емуляція < 1024px: слот міняє кнопку кожні 5 с, перехід —
   розмиття, не стрибок. На 1024px і ширше слота нема, проміжку між
   «Каталогом» і кошиком теж.
3. Десктоп-емуляція < 1024px із мишею: курсор на слоті → підміна чекає, поки
   курсор не піде.
4. Tab на кнопку слота → підміни нема, поки фокус на ній; Enter відкриває
   шторку або /menu відповідно до видимої кнопки.
5. DevTools → Rendering → `prefers-reduced-motion: reduce`: перехід лише
   прозорістю.
6. Відкрити шторку, зачекати 15 с, закрити → у хедері одразу меню, далі такт
   заново.
7. Згорнути вкладку на 30 с, повернутись → у хедері меню.
8. Реальний телефон: шторка тягнеться за ручку і закривається свайпом; тап по
   оверлею і Escape (з клавіатурою) закривають.
9. Порожній сабміт → червона лінія і підпис під полем, запиту нема.
10. Тестове побажання з текстом `тест *_[]()` без контакту → повідомлення в
    адмін-чаті прийшло, символи не зламали відправку, «Контакт: не залишено»,
    сторінка і київський час правильні. Потім те саме з контактом.
11. `curl` на роут з `website: 'x'` → 200, у чаті нічого. З `message: 'ab'` → 400.
12. DevTools → Network → Offline → «Надіслати» → стан `error`, текст
    зберігся, лінк на Telegram веде на канал.
13. Прев'ю Vercel: `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` там уже є (їх
    читають наявні роути), тестове повідомлення з прев'ю доходить.

## Ризики

- `Sheet` з моменту зняття фільтрів каталогу (d20c699) ніде не змонтований у
  проді, тож може мати неспіймані регресії з Mantine 8.3. Перша реальна
  перевірка — пункт 8 чекліста.
- Blur на слоті — перший `filter` в анімації хедера; якщо на слабких
  телефонах перехід смикається, запасний варіант — лишити тільки opacity +
  scale (та сама розмітка, одна властивість менше).
- Такт без зупинки: близько половини часу кнопка меню недоступна. Рішення
  власника; якщо після запуску буде відчутно, перший крок — довший період
  меню (наприклад 8/4), константа одна.
