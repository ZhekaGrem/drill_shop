# Концепція 1 · «Cupertino Native» — специфікація

> Статус: кандидат (рекомендація дизайн-команди для MVP v2). Джерело — пропозиція
> команди від 16.08.2026 поверх дизайн-документації системи.
> Теза: магазин відчувається як системний застосунок iOS — звичні патерни,
> мінімум тертя при покупці.

## 1. Токени (дельта до `globals.css`)

| Токен | Було (світла/темна) | Стане (світла/темна) | Контраст-вердикт |
|---|---|---|---|
| `--accent` | `#0073e6` / той самий | `#007AFF` / `#0A84FF` | ⚠️ `#007AFF` на білому **4.02:1** — лише великий кегль (≥18px або 500+), іконки, контроли. Дрібні текстові лінки ЛИШАЮТЬСЯ на `#0073e6` (4.57:1 ✓) або жирнішають. `#0A84FF` на `#1C1C1E` — 4.66:1 ✓ |
| `--background` (ґрунт, dark) | плівка 0.84 над градієнтом | **OLED `#000000`** (суцільний; градієнт у темній зникає) | — |
| `--surface-card` (dark) | `#1b211f` | `#1C1C1E` (iOS elevated) | текст `#f2f4f3` на ньому — 15.4:1 ✓ |
| `--surface-muted` (dark) | `#262d2a` | `#2C2C2E` | — |
| `--border-subtle` (dark) | `#2c3431` | `#38383A` | картки на OLED без межі; межа лише інпутам |
| Світла тема | | **без змін** | фундамент недоторканний |

**Важлива правка пропозиції.** У тексті команди «картки #000, ґрунт темно-сірий» —
це інверсія справжнього iOS-патерну. Канонічно (і в цій спеці): **ґрунт OLED
`#000000`, картки elevated `#1C1C1E`** — «плаваючі» поверхні виходять саме так,
і зберігається наше правило «картку тримає контраст поверхні».

**Ціна рішення:** у темній темі бренд-градієнт з ґрунту зникає (OLED = суцільний
чорний). Нічний бренд тримають капсули/крапки та hover-градієнт кнопок.
Команда має свідомо це прийняти.

## 2. Герой: Peek-карусель

- Один ряд: картки колекцій на всю ширину мінус 32px, сусідні визирають по ~16px
  з країв; `scroll-snap-type: x mandatory`, снап по центру.
- **Жива 3D-сцена — ЛИШЕ в центральній картці** (IntersectionObserver ≥60%
  видимості → mount, інакше unmount до постера-рендера). Бічні картки завжди
  показують рендер-постер. WebGL-бюджет: 1 сцена в кадрі.
- Всередині активної картки — чинний перемикач дизайнів (крапки/міні-фото за
  наявними правилами), заголовок+опис+капсула/крапка з БД, кнопка «До колекції».
- Порядок карток = `collections.sort_order`. Лічильників немає (peek сам
  підказує сусідів).
- Стан вибраного дизайну зберігається на колекцію (як зараз, словник у state).

## 3. Теми

- Правило 18:00–6:00 **замінюється** системним: інлайн-скрипт читає
  `matchMedia('(prefers-color-scheme: dark)')` (явний вибір із localStorage
  далі перекриває). Слухач `change` — перемикання наживо.
- Тумблер 🌙/☀️ лишається тільки в `DEV_MODE`.

## 4. Позначки

- **«Новинка» = міні-пігулка** біля назви: це чинна капсула (`label_*`) із
  суцільним кольором. Значення: `label_color: '#007AFF'` (світла) — у темній
  капсули з `#0A84FF` не потребують коду: рекомендовано зберігати
  `var(--accent)` у полі, щоб пігулка сама жила в обох темах.
- **Крапка (`badge_*`)** — тихі статуси товарів («класика», «останні розміри»).
- Стікери/градієнтні капсули в цій концепції не використовуються (маркетинговий
  шум мінімізується) — поля лишаються, гайд забороняє.

## 5. Обсяг робіт

| Шар | Зміни |
|---|---|
| `globals.css` | дельта темних токенів + `--accent` пара |
| `Home.tsx` + `home.module.scss` | стек героїв → peek-карусель зі снапом; mount-правило центральної сцени |
| `layout.tsx` (інлайн-скрипт) + `ThemeToggle` | годинник → `prefers-color-scheme` + live-listener |
| БД | **нових полів нема**; лише значення `label_color` |
| Гайд позначок | словник: пігулка = «Новинка», крапка = статуси |

## 6. Ризики / перевірки

- OLED-чорний ґрунт: перевірити чорний навбар/футер — потрібна межа
  `--border-inverse-subtle`, інакше зливаються з ґрунтом.
- Peek + драг-обертання сцени конфліктують по горизонтальному жесту:
  сцена вже має `touch-action: pan-y` — у каруселі жест по сцені обертає
  футболку, свайп по полях картки гортає колекції. Протестувати на телефоні.
- `#007AFF` дрібним текстом — заборонено гайдом (4.02:1).
