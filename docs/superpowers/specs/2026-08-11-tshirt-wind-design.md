# Вітер на 3D-футболці в герої

**Дата:** 2026-08-11
**Гілка:** `v2`
**Статус:** спека затверджена, план не написаний

---

## Задача

3D-футболка в герої обертається і вміє стрибати, але тканина мертва — стоїть
колом. Додаємо постійне делікатне колихання, наче футболка одягнута на людину,
що спокійно йде вулицею: дрібні брижі по полотну, поділ і кінці рукавів
гойдаються найпомітніше, груди й плечі майже нерухомі.

Характер — **рівномірне колихання без поривів** (вибір користувача): спокійно,
передбачувано, в тон стриманій мові Дії.

Числа нижче — цільові орієнтири; точні значення тюняться на око, не втрачаючи
характеру «легко»: рух видно, але він не відволікає від контенту.

## Вигляд і параметри

| Параметр            | Орієнтир                                                     |
| ------------------- | ------------------------------------------------------------ |
| Амплітуда на подолі | ~1–1.5 % висоти моделі (≈ 0.008–0.011 юніта при висоті 0.74) |
| Вага по висоті      | 0 у верхніх ~20 % (плечі/комір), плавний ріст до 1 на подолі |
| Вага рукавів        | додатковий внесок на кінцях рукавів (за \|x\| від осі тіла)  |
| Брижі               | 2 октави синусоїд різних частот і швидкостей уздовж нормалі  |
| Погойд              | легкий загальний рух по X, значно повільніший за брижі       |

Принт запечений у текстуру — хвилюється разом із вершинами сам, окремої роботи
не потребує. Сітка моделі — 44 818 вершин / 78 000 трикутників (перевірено) —
достатньо щільна для гладкого вершинного зміщення.

## Механізм

Вершинний шейдер поверх **наявного** `MeshStandardMaterial` футболки через
`onBeforeCompile` — GLB не змінюється, нових залежностей немає:

- Вагова карта рахується в шейдері з **локальних (модельних) координат**
  вершини: `smoothstep` по висоті + додатковий `smoothstep` по |x| для рукавів.
  Жодних додаткових атрибутів чи текстур ваги.
- Зміщення: сума двох синусоїд (різні частоти/швидкості/фази) уздовж нормалі
  вершини + повільний X-погойд. Все множиться на вагу й амплітуду.
- Час — один uniform (`uWindTime`), оновлюється в наявному useFrame сцени з
  `state.clock.elapsedTime`.
- Зміщення відбувається в модельних координатах **до** modelMatrix, тому вітер
  природно обертається разом із футболкою і стискається/розтягується разом зі
  стрибком — окремої синхронізації не потрібно.
- Нормалі не перераховуємо: на такій амплітуді розбіжність освітлення не
  зчитується оком, а перерахунок коштував би непорівнянно дорожче.

## Архітектура

Все в межах `src/widgets/HeroVisual/`:

- **`useWind.ts`** (новий) — хук: знаходить меш футболки в підготовленій сцені,
  один раз патчить його матеріал (`onBeforeCompile`, явний
  `customProgramCacheKey`, guard-прапорець у `material.userData` — `useGLTF`
  кешує сцену між маунтами, патчити двічі не можна), тримає ref на uniform
  часу. Повертає `step(elapsedTime)` для виклику з useFrame.
- **`TshirtScene.tsx`** — один виклик хука і один рядок у наявному useFrame.
  Компонент лишається < 150 рядків.

Жодного setState, жодних алокацій на кадр: один запис числа в uniform.

## Reduced motion і доступність

- `prefers-reduced-motion` вже гейтить завантаження сцени в HeroVisual —
  вітер зникає разом із нею, нового коду не треба.
- Статичний фолбек-webp без змін.

## Крайові випадки

| Випадок                              | Поведінка                                                       |
| ------------------------------------ | --------------------------------------------------------------- |
| Повторний маунт сцени (кеш useGLTF)  | guard у `material.userData` — матеріал не патчиться вдруге      |
| Фонова вкладка → повернення          | час із `state.clock`; синусоїди неперервні — стрибків руху нема |
| Стрибок під час колихання            | зміщення в модельних координатах — компонується без конфліктів  |
| Обертання                            | те саме — вітер обертається разом із моделлю                    |

## Тестування

Тестової інфри в репо немає. Ручна перевірка:

- брижі видно на подолі й рукавах; плечі/комір практично нерухомі;
- амплітуда «легка»: рух помітний, але не відволікає;
- стрибок і обертання працюють як раніше, вітер їх не ламає;
- увімкнений prefers-reduced-motion → сцени немає, фото на місці;
- `npx tsc --noEmit`, `npm run lint`, `npm run build` зелені.

## Свідомо не робимо (YAGNI)

Пориви вітру, інтерактивний вітер (від миші/скролу), перерахунок нормалей,
зовнішні налаштування сили, вітер деінде поза hero-сценою.
